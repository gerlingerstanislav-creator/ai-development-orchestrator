# Архитектура — обсуждение (не утверждённое решение)

## Основные компоненты
- Web UI и API.
- База проекта, задач, документов, запусков агентов, истории и ссылок на PR.
- Оркестратор этапов и очередь заданий.
- Адаптеры к Codex и Claude Code.
- Изолированные рабочие окружения с отдельными Git-ветками.
- Интеграция GitHub с ограниченными правами.

## Принципы
- Задача ≠ запуск агента: запусков может быть несколько, с отдельным состоянием.
- Этап ≠ запущенный процесс: этап может ждать человека, лимит или другую задачу.
- Контекст агента собирается по роли, задаче и документам, но история сохраняется.
- При появлении новой связанной задачи пересматривать план безопаснее на контрольной точке, а не переписывать на лету контекст уже выполняющегося процесса.
- Действия с внешними эффектами (коммиты, PR, merge) должны учитывать повторы и быть проверяемыми.
- Секреты и авторизация агентов не должны находиться в репозитории либо доступной агентам документации.

## Вопросы на согласование
1. Backend: TypeScript/Node.js или Python/FastAPI.
2. Orchestration: Postgres-based очередь на MVP или durable workflow engine.
3. Auth: доступ к сервису и изолированное подключение GitHub/моделей.
4. Frontend: React (например Next.js или Vite).
5. Hosting: сервер, CI/CD, домен, резервные копии и мониторинг.
6. Ограничения и доступность программного серверного подключения Codex и Claude.

Никакой из перечисленных вариантов стека пока не выбран окончательно.
