# Agent Runtime — архитектура, полномочия и включение

## Назначение

Новый режим `AGENT_RUNTIME_ENABLED` заменяет определение намерения пользователя
регулярными выражениями на автономную работу Codex CLI с MCP-инструментами.
Исходное сообщение передаётся модели без перефразирования вместе с контекстом
проекта, утверждёнными инструкциями роли, перепиской и ограниченным объёмом
накопленных уроков. Модель сама решает, какие документы читать, какие операции
выполнять, когда отвечать обычным текстом и когда инициировать долгий процесс.

**Нейросеть выбирает действия, а сервис выполняет и фиксирует операции.**
Это не выдача прямого SQL-доступа или общего административного токена агенту.

## Компоненты

1. `assistant.ts` создаёт отдельную сессию агента, собирает контекст и
   вызывает `POST /agent` Codex Runner. Секрет сессии не включается в prompt.
2. `apps/codex-runner/server.mjs` запускает `codex exec` с локально
   подключённым MCP stdio-сервером `agent-mcp.mjs`. Codex работает через
   действующую авторизацию ChatGPT; платный токенный API не требуется.
3. MCP-сервер получает схему доступных инструментов от
   `/internal/agent-tools/catalog` и передаёт вызовы на
   `/internal/agent-tools/call`, подписывая их токеном текущей сессии.
4. `agent-tool-executor.ts` выполняет запросы к данным и создаёт задачи
   в допустимых начальных стадиях. `agent-tool-routes.ts` проверяет токен
   сессии, ограничивает область проектом, проверяет ключ идемпотентности,
   атомарно сохраняет успешные операции и журнал в одной транзакции.
5. Запросы на импорт/пересборку документации сохраняются в базе как
   `queued`, и **только после COMMIT** инициируется Temporal. После рестарта
   API незавершённые запуски автоматически восстанавливаются. Повторный вызов
   с тем же ключом возвращает тот же job ID.
6. `agent_memory` хранит опыт и предложения об изменении инструкций.
   Утверждённые предложения становятся доступным контекстом будущих
   запросов. Неутверждённые предложения не включаются в обязательные правила.

## Модель ответственности

| Участник | Решает | Фактически выполняет |
|---|---|---|
| Codex-агент | Как понимать поручение и какие инструменты использовать | Анализ, тексты, последовательность вызовов инструментов |
| API приложения | Допустимость и целостность изменений | Записи PostgreSQL, контроль ревизий, audit, разрешения проекта |
| Temporal | Продолжительность процессов и повтор шагов | Импорт, пересборка ТЗ и другие уже существующие workflow |
| Codex Runner | Как выполнить команду Codex | Запуск CLI, доступ к MCP, ограниченная файловая среда |
| GitHub-интеграция | Проверка статусов и правил слияния | Фактические commit, push, PR и merge |
| Владелец продукта | Подтверждение спорных бизнес-решений | Ответы на вопросы и согласование изменений |

Контракт инструментов ориентирован на предметные действия, а не на сырые
публичные REST-маршруты: `documents.create`, `documents.update`,
`documents.changeset`, `tasks.create`, `documentation.import`,
`documentation.rebuild`, `memory.record` и т. д.

## Надёжность

- Каждая сессия привязана к пользователю и проекту, имеет ограниченный срок.
- `expected_revision` предотвращает перезапись документа, который был
  изменён после чтения агентом.
- В `documents.changeset` все операции и audit сохраняются либо целиком,
  либо откатываются.
- `idempotency_key` позволяет безопасно повторять изменяющие запросы после
  потери ответа от сети: одинаковый ключ с другими аргументами запрещён.
- Тела документов, пользовательских сообщений и инструкции не сохраняются
  в журнал инструмента открытым текстом; вместо них журнал хранит размер и хеш.
- PostgreSQL хранит результат и историю инструментов. Заявление AI об
  успешном действии не заменяет реально сохранённый результат.
- Долгоживущие изменения документации запускаются через Temporal и
  восстанавливаются по прежним идентификаторам, а не новым заданиям.

## Включение и откат

**По умолчанию `AGENT_RUNTIME_ENABLED=false`.** Это сознательная мера
совместимости; новый механизм не заменяет существующие чаты после простого
обновления до тех пор, пока не пройдена проверка реальным Codex CLI.

Для изолированной проверки установите `AGENT_RUNTIME_ENABLED=true` на
развёрнутой тестовой платформе и пересоздайте `api` и `codex`.
В Codex Runner должна быть действующая авторизация ChatGPT.

Минимальные проверки вручную:

1. Спросить аналитика о текущем ТЗ — он должен самостоятельно вызвать
   `documents.list/read` и дать ответ обычным русским текстом.
2. Попросить создать тестовую страницу — получить реальный UUID и
   проверить создание и аудит в сервисе.
3. Повторить операцию с ключом идемпотентности — убедиться в отсутствии
   дубликата.
4. Поручить пересобрать ТЗ — убедиться в наличии одного Temporal job,
   сохранении старых документов и контрольных точек.
5. Перезапустить API во время ожидающего запуска — проверить
   восстановление работы без нового job ID.
6. Спросить агента о содержании документа из *другого* проекта —
   доступ должен быть отклонён.

При выявленной ошибке переключить `AGENT_RUNTIME_ENABLED=false`,
не откатывая схему и не удаляя `agent_sessions`, `agent_tool_events` и
`agent_memory`. Старый механизм чата останется доступным.

## Пока не охвачено

- В общий MCP-цикл пока переведены проектный чат и чат аналитика.
  Разработчик, QA-агент и документатор продолжают исполнять свои
  специализированные процедуры.
- Не все возможности GitHub, переходов workflow и тестирования представлены
  инструментами MCP. Их следует добавлять поверх существующих проверяемых
  backend-операций, не дублируя контроль бизнес-стадий.
- Произвольное многоминутное рассуждение Codex внутри одного CLI-вызова пока
  ограничено временем запроса; длительные операции обязательно запускаются
  через Temporal.
- Наличие зелёных CI-тестов не заменяет реального smoke-теста с
  авторизованным Codex CLI, MCP и PostgreSQL в Docker.

Репозиторий `ideas` при реализации этого режима не изменяется.
