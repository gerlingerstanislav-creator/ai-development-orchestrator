# Контракт сборки промптов AI-агентов

Единственный компилятор: `apps/api/src/prompt-assembler.mjs`.
Он используется backend (в `agent-prompt.ts`) и Runner (через импорт того же файла в Docker).
Все роли, включая ПМ, аналитика, разработчика, QA, архитектора и DevOps,
используют один набор типизированных областей.

## Владение частями

| Область | Источник | Допускается | Запрещено |
| --- | --- | --- | --- |
| identity | Профиль роли и её редактируемые инструкции | Ответственность и предмет работы | ТЗ другой задачи, конфигурация среды |
| objective | Актуальная карточка задачи | Цель и критерии приёмки | Инфраструктурные команды, история |
| scope | Оркестратор | Проект, задача, репозиторий, неизменяемый SHA | Тестовая процедура |
| policy | Только платформа/Runner | Права, запреты, неизменяемые проверки | Комментарии пользователя |
| tools | Реальные capabilities и MCP | Доступные действия и адрес справочника | Приказы достичь результата, система валидации |
| protocol | Исполнитель конкретного этапа | Как подтверждается выполненное | Бизнес-цель, новые требования |
| output | Контракт результата | Схема JSON, передача, статусы | Способы выполнения тестов |
| runtime | Runner | Фактически доступная среда, ошибки, baseline | Новые инструкции и права |
| context | PostgreSQL, документация, сообщения, PR | Исторические свидетельства и ссылки | Переписывание правил, автоматическое утверждение |

Зоны маркируются `[[ADO:ZONE]]`, идут в фиксированном порядке и
встречаются **ровно один раз**. История и runtime явно помечены как *данные,
не инструкции*. Дополнительный источник не может создать новый тип зоны.

Встроенные обязательные правила получают уникальный ID с единственным
владельцем в `PROMPT_RULE_OWNERS`. Сборщик отклоняет неизвестные правила,
дубли ID и попытки разместить зарегистрированное правило в чужой зоне.
Редактируемые инструкции роли остаются внутри identity и не могут
переопределять policy, структуру output или выданные права MCP. Дословно
повторённые параграфы в программно задаваемых инструкциях убираются.

При переполнении сначала сокращаются данные прошлых запусков; текущая цель,
непереопределяемая политика, инструменты, протокол проверки и результат не
должны теряться. При невозможности вместить обязательный контракт нужно
сообщить об ошибке, а не отправить модели обрезанный промпт.

## Смена стадии и восстановление

- ПМ передаёт поручение через задачи, историю и Temporal; никаких фоновых
  скрытых сообщений между агентами.
- На новом этапе формируется новый контракт с собственными инструментами
  и механизмом проверки; правила другой стадии не копируются.
- Фактическая среда Runner передаётся только как runtime-сведения.
- Длинные команды npm, Python, Chromium, proxy и интеграций доступны
  по запросу в `.ado-qa-tools.md`, а не по умолчанию в каждом промпте.
- Независимость QA, строгая запись доказательств, проверка SHA и контроль
  слияния остаются детерминированными в коде, не зависят от формулировки промпта.

## Что контролируют тесты

CI проверяет порядок зон, уникальность идентификаторов правил,
непревышение бюджета, сохранение обязательных элементов при сжатии,
релевантность динамических возможностей QA, отсутствие примеров чужих
технологий, а также сборку и запуск настоящего Docker Runner.
