# Универсальный Kanban и приёмка результата

Состояние продукта **не равно** этапу выполнения AI. Одна задача может одновременно иметь несколько исполнителей, QA-прогонов и Temporal-процессов.

## Доска

Пять постоянных колонок: **Бэклог → К работе → В работе → На приёмке → Готово**.

| `tasks.board_status` | Смысл |
| --- | --- |
| `backlog` | Идея или ещё не включённая в план задача |
| `todo` | Запланирована, можно брать в работу |
| `in_progress` | Работа ещё не закончена: анализ, реализация, QA, выкладка, документация или ожидание технического шага |
| `acceptance` | Технический workflow закончен, владелец решает, соответствует ли результат цели |
| `done` | Результат принят владельцем либо автоматически по заранее разрешённой политике |

Отдельные представления, **без новых стадий**: отложенные, требуют внимания, архив. Отменённые задачи управляются существующим механизмом отмены, а не переходят в `done`.

### Технический workflow остаётся самостоятельным

Существующее поле `tasks.stage` и его проверки (QA, ветки, PR, слияние, deployment и документация) **не заменяются** пятью состояниями Kanban. Доска отображает `board_status`, технический этап — подпись внутри карточки и подробный workflow в ней. Передача между ролями не двигает карточку по колонкам до завершения полного результата.

Миграция v21 заполняет новое поле без утраты данных. Все исторические `stage='done'` остаются в `board_status='done'` и не требуют повторной приёмки. Вновь завершённая задача переходит на приёмку, кроме разрешённой автоматической приёмки и закрываемых вопросов документации.

## Политика приёмки

- `undecided` (по умолчанию) — до фактического завершения технического процесса решение о необходимости ручной приёмки может быть принято отдельно; без него задача безопасно ожидает владельца.
- `manual` — после полного workflow карточка ожидает явного подтверждения владельца.
- `automatic` — после завершения полного workflow можно перевести карточку в `done` без дополнительного клика; все прежние QA/CI/PR/выкладка остаются обязательны, если применимы.

Ручное перетаскивание в «На приёмке» или «Готово» **не разрешено**. Сервер принимает результат только при техническом `stage='done'`. Замечания к приёмке сохраняются с историей; уже слитый PR не откатывается и не перезаписывается, для исправлений требуется связанная задача. Отдельная автоматизация создания этой задачи ещё не внедрена.

## Отложенные и архив

- Отложить можно задачу без активных запусков. Это **не** кнопка остановки Temporal: выполняющийся процесс сначала необходимо остановить штатным способом.
- При отложении сохраняются контекст и технический этап; на доске задача доступна через представление «Отложенные», с необязательной датой возврата. Возврат не запускает Codex автоматически.
- Архив допустим только после подтверждённого `done`; история, артефакты и привязки сохраняются. Восстановление возвращает карточку в доску без изменения технической стадии.

## Почему это важно

Снимки сайта не должны идти по маршруту «аналитик → разработчик → QA» только из-за устройства Kanban. PM выбирает набор инструментов и при необходимости исполнителя; доска отслеживает достижение результата. Подробности исполнения, конкуренция сессий и ошибки остаются в Центре процессов.

## Проверки

Регрессия должна подтверждать: миграцию существующих задач, независимость `stage` и `board_status`, QA внутри «В работе», защиту приёмки, альтернативную автоматическую приёмку, сохранность отложенных задач, архив и возвращение документационных вопросов в `done`.
