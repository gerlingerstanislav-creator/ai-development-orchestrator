# Универсальный workflow — AI Development Orchestrator

Один неизменяемый безопасный конвейер используется для большинства продуктовых задач:

**Бэклог → Анализ → Разработка → Тестирование → Очередь слияния PR → Выкладка → Документация → Готово.**

## Кто отвечает

| Этап | Ответственный | Другие участники | Выходной критерий |
| --- | --- | --- | --- |
| Бэклог | PM | Аналитик | Запрос принят, цель и приоритет определены |
| Анализ | Аналитик BA+SA | PM, архитектор, QA | Проверяемые требования, критерии приёмки, открытые вопросы разрешены |
| Разработка | Разработчик | Архитектор, QA | PR на определённом SHA, локальные проверки и код-ревью |
| Тестирование | QA | Разработчик, аналитик | Подтверждённые кейсы; дефекты возвращены разработчику |
| Слияние PR | Система | PM, архитектор | QA, ревью и требуемый CI подтверждены для текущего SHA |
| Выкладка | DevOps | Разработчик, QA | Успешный релиз и проверка здоровья либо явно зафиксированный пропуск |
| Документация | Документатор | Аналитик, разработчик | Документация отражает слитую реализацию |
| Готово | PM / система | — | Обязательные результаты сохранены, нет активных блокировок |

PM контролирует исключения и согласование важных решений, а не вручную переводит каждую задачу.
Вопросы владельцу — состояние ожидания с возвратом к исходному этапу. При ошибке QA задача возвращается в разработку, проверяется тот же PR с новым SHA.
Провалы CI, merge и выкладки не являются успешными переходами.

## Профили планирования

- **Быстрый:** краткая проработка и фокусные проверки для маленьких задач низкого риска.
- **Стандартный (по умолчанию):** полный баланс анализа, разработки, независимого QA и документации.
- **Расширенный:** углублённая архитектурная оценка, риск-анализ, миграции, безопасность, регрессия, план отката.

Выбранный профиль хранится у проекта и используется как контекст планирования для агентов.
**Профиль не меняет обязательные переходы и не является разрешением пропустить доказательства успешного анализа, ревью, QA, CI, слияния или выкладки.**
Режим пропуска выкладки конфигурируется отдельно и записывается в историю.

Изменение профиля не влияет задним числом на уже выполненные шаги и не запускает задачи автоматически.
