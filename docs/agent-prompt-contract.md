# Контекст и промпты AI-агентов

## Принцип

Любой вызов агента содержит роль, доступные инструменты, текущее поручение и только связанные с ним сведения. Все задачи, документы и всю историю проекта не загружаем автоматически.

Общий конструктор `composeAgentPrompt`: `apps/api/src/agent-prompt.ts`. Обязательное текущее поручение не вытесняется историей. Дополнительные блоки ограничены, слишком большой обязательный запрос вызывает явную ошибку вместо молчаливого обрезания. Кодекс-раннер дополняет задание неизменными правилами безопасного запуска.

## История и инструменты

Полная история и решения сохраняются в PostgreSQL. ПМ получает текущее сообщение, одно поручение и максимум три коротких реплики той же темы. Старые решения и обсуждения запрашиваются адресно через `pm.decisions.list`, `discussions.read` и `history.search`; задачи и документы — через `tasks.*`, `documents.*`, `knowledge.*`. Права на операции проверяются сервером.

Разработчику передаются актуальное ТЗ конкретной задачи и обратная связь QA. QA получает отдельную рабочую копию репозитория и файл `.ado-qa-plan.json` с полным планом проверок: огромный JSON больше не вставляется в запрос к модели.

## Просмотр запросов

Промпты записываются в `agent_prompt_audit` по проекту и процессу. Финальные промпты Codex Runner отправляет во внутренний `POST /internal/agent-prompt`. Администратор видит записи через `GET /api/projects/:id/processes/:processId/prompts` в Центре процессов. Старые запуски до обновления записей не имеют.

Перед записью известные токены маскируются. Хранение диагностического текста не должно блокировать основную задачу. Аудит — диагностический инструмент; он не предназначен для хранения или передачи секретов.

## Проверки

`apps/api/tests/agent-prompt.test.mjs` проверяет бюджет, приоритет текущего поручения и маскировку секретов. CI запускает TypeScript, сборку, синтаксис Runner и тесты.
