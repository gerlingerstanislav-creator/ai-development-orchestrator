# Границы первого MVP

## Пользовательский сценарий
1. Участник создаёт проект, подключает репозиторий и создаёт задачу через канбан либо чат.
2. Аналитик изучает код и документацию, формулирует требования и вопросы.
3. В зависимости от настройки этапа следует автоматический переход либо подтверждение человека.
4. Разработчик изменяет код в отдельной рабочей копии и ветке.
5. Тестировщик выполняет проверки, возвращает ошибки либо создаёт результат для ревью.
6. PR можно просмотреть, прокомментировать и обработать в интерфейсе приложения в пределах предоставленных разрешений.

## Состав
- Многопользовательские проекты, участники.
- Канбан и список задач; эпики, задачи, подзадачи, базовые зависимости.
- Документация, доступная человеку и ИИ, с историей изменений.
- Чат проекта для создания задач и базового управления.
- Ролевые агенты и учёт запусков/результатов/ошибок.
- Базовая очередь и восстановление с контрольной точки.
- Связь с GitHub и работа с PR.

## На следующий этап
- Интеллектуальная группировка родственных задач, автоматическое перераспределение задач на лету.
- Широкий конструктор произвольных процессов, сложная система доступа.
- Автоматический деплой в production, распределённая инфраструктура.

Здесь зафиксировано предполагаемое содержание MVP; технические подходы ещё обсуждаются.
